# Content agents

Tools a **developer** runs on a laptop to turn a teacher's curriculum pages
into a **draft** of chapter content. They are not part of the product.

Nothing here ships. The child-facing PWA is a static export that talks to
nothing but its own assets — it has no backend, no database, no
authentication, no API, and no key. These scripts run outside it, write JSON
a human then reads, and that is the whole relationship. Neither Drive nor the
Sheet is ever a runtime dependency of the app.

Only one agent exists so far:

| Agent | What it does |
| --- | --- |
| `memory-verse` | Reads a chapter's curriculum pages, finds the memory verse, and generates a practice drill for each of the seven classes. |

---

## The shape of a run

```
--fetch            Drive → pages on disk, + the teacher's row from the Sheet
(Claude looks)     reads the pages, writes down what it can see
--from-extraction  gates → cross-check → the seven-class ladder → draft
```

**No AI API is called at any point, and no API key of any kind is required.**
The step that reads a photograph of a printed page is done by a Claude session
looking at the downloaded images — which is why the run is in two halves with
a person in the middle, and why it cannot run on a cron. That is the trade
this version makes deliberately: supervised and verifiable now, unattended
later if it is ever wanted.

Everything after the verse — the seven difficulty variants — is generated by
ordinary code in `memory-verse/ladder.mjs`, with no model involved at all. So
tuning the ladder is a diff, not a prompt.

### Two sources, always

Teachers upload the curriculum pages **and** type the verse into the editorial
Sheet. That looks like duplicated effort and is the most valuable thing in the
workflow: every verse has two independent origins — a photograph of the book,
and a person who held the book and typed.

The agent compares them. Case, spacing, punctuation and the `St`/`Saint`
honorific are forgiven; a different word, a different chapter or a different
book is not. **A disagreement is never resolved automatically** — the run
stops, writes `REVIEW-REQUIRED.txt` with both readings side by side, and a
person decides.

When there is no Sheet row the run still works, and says so in the draft. A
verse confirmed by nobody is a weaker claim than one two sources agree on, and
the draft is honest about which it got.

## Running it

```bash
# 1. download the pages and the teacher's Sheet row
npm run agent:memory-verse -- --class beginner --chapter 01 --fetch

# 2. look at the pages, fill in the `extraction` block of the request file

# 3. validate, cross-check, generate the draft
npm run agent:memory-verse -- --class beginner --chapter 01 --from-extraction
```

`--class` is one of `nursery`, `beginner`, `primary`, `junior`,
`intermediate`, `senior`, `young-adult`. `--chapter` is `01`–`20`.

Class is part of the content's identity: `Beginner / Chapter 01` and
`Primary / Chapter 01` are different curricula, not two views of one. So a run
names both, always.

Other flags:

```bash
--source-dir ./pages   read a folder on this machine instead of Drive
--no-upload            keep a Drive-sourced draft on disk only
```

```bash
npm run agent:test     the generators and gates — no network, no credentials
```

### Step 2, in detail

`--fetch` writes a request to
`agents/.state/extractions/<class>-chapter-<nn>.request.json` with the
`extraction` block empty. Filling it in is the supervised step: open each file
listed under `source.files`, **look at it**, and write down what is on the
page.

```json
"extraction": {
  "verseText": "...",
  "reference": "...",
  "sourceFile": "page-01.png",
  "confidence": "high",
  "ambiguities": []
}
```

The rules travel with the request, in its `instructions` array:

- Preserve the exact wording visible on the page, character for character.
- Do **not** correct, complete or modernise the verse using Bible knowledge.
- Do **not** substitute a translation you recognise as more standard.
- Do **not** infer a word that is obscured — say it is obscured.
- Do **not** choose between candidate verses — list them and stop.
- `confidence` is `high` only when the verse and reference are plainly legible.
- Anything uncertain goes in `ambiguities`. **A non-empty list stops the run.**

### What comes out

- `agents/.drafts/<class>/chapter-<nn>/memory-verse-draft-<class>-chapter-<nn>.json`
- `agents/.drafts/<class>/chapter-<nn>/README.md` — the same thing for a human
- and, when the source was Drive, a copy in that chapter's
  **`06 - Memory Verse`** folder

Both are **drafts**. Nothing is marked approved, `07 - Approved Assets` is
never written to, the deployed app is never modified, and nothing is pushed
anywhere. Approval is a human act and stays one.

If anything is unsure — a low confidence, a listed ambiguity, a verse too
short to be a verse, a reference with no numbers in it, or a disagreement with
the teacher's Sheet — the run stops and writes `REVIEW-REQUIRED.txt` instead,
with both readings and the page checksums. It does not guess and it does not
choose. A guessed Bible verse taught to a child is the worst thing this tool
could do, so the failure mode is always "a person looks at it".

## Credentials

Everything lives in **`.env.local`**, which is git-ignored and never read by
the app. Copy `.env.example` and fill it in.

```
GOOGLE_OAUTH_CLIENT_ID=...             # Drive: not needed with --source-dir
GOOGLE_OAUTH_CLIENT_SECRET=...
GOOGLE_OAUTH_REFRESH_TOKEN=...
DRIVE_LIBRARY_ROOT_ID=...              # optional; found by name otherwise
SSC_SHEET_ID=...                       # optional; enables the second opinion
```

**There is no AI API key here, and none is needed.** Extraction is Claude
looking at the pages.

Never commit this file. Never paste a credential into `src/`, `public/`, or
any `NEXT_PUBLIC_*` variable — anything with that prefix is compiled into the
bundle a child downloads.

### The Drive credentials

Only needed to read curriculum from Drive. `--source-dir` skips all of this,
and is the zero-credential way to run the first test.

1. In the [Google Cloud console](https://console.cloud.google.com/), create (or
   pick) a project and enable the **Google Drive API** and the
   **Google Sheets API**.
2. **APIs & Services → Credentials → Create credentials → OAuth client ID**,
   type **Desktop app**. Note the client ID and secret.
3. Get a refresh token for the scope `https://www.googleapis.com/auth/drive`
   — the [OAuth 2.0 Playground](https://developers.google.com/oauthplayground/)
   is the quickest route (use your own client ID/secret via the gear icon, so
   the token belongs to your project). That one scope covers the Sheet too.
4. Put all three in `.env.local`.

The account you authorise needs read access to the curriculum library and the
Sheet, and write access to the `06 - Memory Verse` folders. Nothing else.

**The teacher's source files are never touched.** The agent reads
`01 - Curriculum Source` and writes only to `06 - Memory Verse`. It does not
move, rename, modify or delete anything the teacher uploaded, it does not
change the folder architecture, and it never writes a cell of the Sheet.

### The Sheet

`SSC_SHEET_ID` is the id in the Sheet's own URL. Optional — without it a run
works and records that the verse had no second opinion.

The agent looks for a tab whose name matches the class, then a row whose
Chapter column matches. It will **not** fall back to a nearby tab: picking a
plausible one is how a Beginner draft ends up carrying a Primary verse. If
there is no matching tab it says so, and names the tabs the Sheet actually
has.

### Gemini — optional, and not currently used

`agents/shared/providers/gemini.mjs` and `agents/memory-verse/extract.mjs`
still exist and still work. **Nothing imports them**, `GEMINI_API_KEY` is not
required, and no run calls them.

They are kept because they are cleanly isolated and because the prompt in
`extract.mjs` is the distilled form of a lesson worth not relearning: exactly
what has to be forbidden, in writing, before a model transcribes instead of
improves. If an unattended pipeline is ever wanted, that is where it starts.
Until then, treat them as documentation, not as a dependency.

## What the pages can be

`.jpg` · `.jpeg` · `.png` · `.webp` · `.pdf`

`--fetch` downloads them to `agents/.state/pages/<class>/<chapter>/` and they
are read by looking at them. There is no OCR service, no document-processing
step and no AI API call. Anything else in the folder is named on screen and
skipped rather than silently ignored.

## State, and what is git-ignored

```
agents/.state/pages/<class>/<chapter>/        downloaded curriculum pages
agents/.state/extractions/<slug>.request.json the request, and Claude's reading
agents/.state/runs/<slug>.json                where a run stopped and why
agents/.drafts/<class>/chapter-<nn>/          the draft, and REVIEW-REQUIRED.txt
```

**`agents/.state/` and `agents/.drafts/` are both git-ignored**, and must stay
that way: they hold photographs of a teacher's book and the text read off
them. Neither belongs in a public repository or in the app.

Every page is recorded with its size, Drive's md5 and a sha256 taken at
download. That is what makes the provenance falsifiable — a year from now you
can re-download the folder and prove the pages are the ones this verse was
read from, or discover that they are not.

## Layout

```
agents/
  shared/
    config.mjs              env + .env.local, the only place secrets are read
    classes.mjs             the seven classes and the Drive folder names
    files.mjs               which uploads count as a curriculum page
    drive/client.mjs        Drive REST v3 over fetch — no googleapis dependency
    drive/sheet.mjs         the teacher's own entry, read-only
    state/store.mjs         the request, run state and draft writer
    provenance/record.mjs   what was read, by whom, when, and how sure
    providers/gemini.mjs    NOT USED — kept for a possible unattended pipeline
  memory-verse/
    run.mjs                 the CLI: --fetch and --from-extraction
    gates.mjs               every check a verse must pass. No network, no AI.
    ladder.mjs              the seven generators — no AI, just code
    tokenize.mjs            splitting a verse into words, phrases and clauses
    selftest.mjs            npm run agent:test
    extract.mjs             NOT USED — the Gemini prompt, kept as documentation
```

## Reviewing a draft

There is a dev-only page for judging the difficulty ladder as a child would
meet it, in the real interaction player:

```bash
npm run dev
# → http://localhost:3000/debug/memory-verse
```

It renders nothing in a production build. Every class is playable from it,
and "Show what the agent wrote" prints the JSON underneath.

The thing to look for is that the seven rungs actually get harder, and get
harder *in kind* rather than in quantity:

| Class | What it asks for |
| --- | --- |
| Nursery | recognise the ending of a phrase |
| Beginner | choose the one missing word, with the line either side of it |
| Primary | order a handful of phrases |
| Junior | choose the next word, with only the line before it |
| Intermediate | rebuild the whole verse from single words |
| Senior | rebuild it, then recognise the reference among four |
| Young Adult | rebuild it, then type the reference from memory |
