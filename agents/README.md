# Content agents

Tools a **developer** runs on a laptop to turn a teacher's curriculum pages
into a **draft** of chapter content. They are not part of the product.

Nothing here ships. The child-facing PWA is a static export that talks to
nothing but its own assets — it has no backend, no database, no
authentication, no API, and no key. These scripts run outside it, write JSON
a human then reads, and that is the whole relationship. Drive is never a
runtime dependency of the app, and neither is Gemini.

Only one agent exists so far:

| Agent | What it does |
| --- | --- |
| `memory-verse` | Reads a chapter's curriculum pages, finds the memory verse, and generates a practice drill for each of the seven classes. |

---

## The shape of a run

```
Drive  →  download  →  Gemini (once)  →  the verse  →  local generation  →  draft
```

Exactly one AI request per chapter, and only to read the pages. Everything
after that — the seven difficulty variants — is generated by ordinary code in
`memory-verse/ladder.mjs`, with no model involved. The expensive step is
cached by content hash, so re-running a chapter whose pages have not changed
costs nothing at all.

---

## Running it

```bash
# The normal case: read Drive, write a draft
npm run agent:memory-verse -- --class beginner --chapter 01

# Without Drive — read pages from a folder on this machine
npm run agent:memory-verse -- --class beginner --chapter 01 --source-dir ./pages

# Generate locally, upload nothing
npm run agent:memory-verse -- --class beginner --chapter 01 --no-upload

# Use only what is already cached; never call Gemini
npm run agent:memory-verse -- --class beginner --chapter 01 --dry-run

# The generators' own tests — no network, no key needed
npm run agent:test
```

`--class` is one of `nursery`, `beginner`, `primary`, `junior`,
`intermediate`, `senior`, `young-adult`. `--chapter` is `01`–`20`.

Class is part of the content's identity: `Beginner / Chapter 01` and
`Primary / Chapter 01` are different curricula, not two views of one. So a
run names both, always.

### What comes out

- `agents/.drafts/<class>/chapter-<nn>/memory-verse-draft-<class>-chapter-<nn>.json`
- `agents/.drafts/<class>/chapter-<nn>/README.md` — the same thing for a human
- and, when the source was Drive, a copy in that chapter's
  **`06 - Memory Verse`** folder

Both are **drafts**. Nothing is marked approved, `07 - Approved Assets` is
never written to, the deployed app is never modified, and nothing is pushed
anywhere. Approval is a human act and stays one.

If the extractor is not confident it found a real verse, the run stops and
writes `REVIEW-REQUIRED.txt` instead, with everything the model returned. It
does not guess. A guessed Bible verse taught to a child is the worst thing
this tool could do, so the failure mode is always "a person looks at it".

## Credentials

All of it lives in **`.env.local`**, which is git-ignored and never read by
the app. Copy `.env.example` and fill it in.

```
GEMINI_API_KEY=...
GEMINI_MODEL=gemini-2.0-flash          # optional

GOOGLE_OAUTH_CLIENT_ID=...             # only for --source-dir-less runs
GOOGLE_OAUTH_CLIENT_SECRET=...
GOOGLE_OAUTH_REFRESH_TOKEN=...
DRIVE_LIBRARY_ROOT_ID=...              # optional; found by name otherwise
```

Never commit this file. Never paste a key into `src/`, `public/`, or any
`NEXT_PUBLIC_*` variable — anything with that prefix is compiled into the
bundle a child downloads.

### The Gemini key — free tier only

1. Go to <https://aistudio.google.com/apikey>.
2. Create a key in a project with **no billing account attached**. This is the
   protection that matters: a project that cannot be billed cannot generate a
   bill.
3. Put it in `.env.local` as `GEMINI_API_KEY`.

This project runs on the free tier and only the free tier. When the quota is
exhausted the agent stops, saves its state, and tells you to run it again
later. It does not switch providers, does not enable billing, and does not sit
in a retry loop burning tomorrow's allowance. One chapter is one request, so
the free tier is enormously more than enough.

`GEMINI_MODEL` is settable because free-tier model names change; a name
hard-coded in source becomes a 404 on somebody's laptop six months from now.
A `404` from a run means the model name needs updating, not that anything is
broken.

### The Drive credentials

Only needed to read curriculum from Drive. `--source-dir` skips all of this.

1. In the [Google Cloud console](https://console.cloud.google.com/), create (or
   pick) a project and enable the **Google Drive API**.
2. **APIs & Services → Credentials → Create credentials → OAuth client ID**,
   type **Desktop app**. Note the client ID and secret.
3. Get a refresh token for the scope `https://www.googleapis.com/auth/drive`
   — the [OAuth 2.0 Playground](https://developers.google.com/oauthplayground/)
   is the quickest route (use your own client ID/secret via the gear icon, so
   the token belongs to your project).
4. Put all three in `.env.local`.

The account you authorise needs read access to the curriculum library and
write access to the `06 - Memory Verse` folders. Nothing else.

**The teacher's source files are never touched.** The agent reads
`01 - Curriculum Source` and writes only to `06 - Memory Verse`. It does not
move, rename, modify or delete anything the teacher uploaded, and it does not
change the folder architecture.

## What the pages can be

`.jpg` · `.jpeg` · `.png` · `.webp` · `.pdf`

Images and PDFs are sent to Gemini as inline base64 in a single request and
read directly; there is no separate OCR service and no paid
document-processing step. Anything else in the folder is named on screen and
skipped rather than silently ignored.

---

## Caching

`agents/.state/extractions/<class>-chapter-<nn>.json` holds what the model
read, keyed by a SHA-256 fingerprint of the source files (name + size +
Drive's own checksum). Re-running a chapter reuses it and says
`extraction: cached (no Gemini request)`. Change a page in Drive and the
fingerprint changes, so the next run re-reads it.

`agents/.state/` and `agents/.drafts/` are both git-ignored: they hold
teacher curriculum and model output, neither of which belongs in a public
repository.

## Layout

```
agents/
  shared/
    config.mjs              env + .env.local, the only place secrets are read
    classes.mjs             the seven classes and the Drive folder names
    drive/client.mjs        Drive REST v3 over fetch — no googleapis dependency
    providers/gemini.mjs    one request, free tier, quota handled honestly
    state/store.mjs         the extraction cache, run state and draft writer
    provenance/record.mjs   what was read, by what, when, and how sure
  memory-verse/
    run.mjs                 the CLI
    extract.mjs             the prompt, the response schema, and the gates
    ladder.mjs              the seven generators — no AI, just code
    tokenize.mjs            splitting a verse into words, phrases and clauses
    selftest.mjs            npm run agent:test
```

## Reviewing a draft

There is a dev-only page for judging the difficulty ladder as a child would
meet it, in the real interaction player:

```bash
npm run dev
# → http://localhost:3000/debug/memory-verse
```

It renders nothing in a production build. Every class is playable from it,
and "Show what the agent wrote" prints the JSON underneath.

The thing to look for is that the seven rungs actually get harder, and get
harder *in kind* rather than in quantity:

| Class | What it asks for |
| --- | --- |
| Nursery | recognise the ending of a phrase |
| Beginner | choose the one missing word, with the line either side of it |
| Primary | order a handful of phrases |
| Junior | choose the next word, with only the line before it |
| Intermediate | rebuild the whole verse from single words |
| Senior | rebuild it, then recognise the reference among four |
| Young Adult | rebuild it, then type the reference from memory |
